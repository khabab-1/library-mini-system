# Mini Library System — نظام إدارة مكتبة

مشروع تدريبي صغير بواجهة ويب عربية (RTL)، مبني باستخدام Python وFlask وSQLite. يحتوي على إضافة الكتب والبحث والإعارة والإرجاع والحذف مع التحقق من المدخلات، واختبارات آلية باستخدام pytest.

## 1) المتطلبات
- Python 3.10 أو أحدث
- اتصال بالإنترنت مطلوب فقط عند تثبيت الحزم (ولتحميل خط Cairo اختيارياً في المتصفح).

## 2) التثبيت والتشغيل على Windows
افتح CMD أو PowerShell داخل مجلد المشروع ثم نفّذ:

```bash
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements.txt
py -m flask --app app seed
py app.py
```

افتح المتصفح على: http://127.0.0.1:5000

إذا كان الأمر `py` غير متاح، جرّب `python` بدلاً منه.

## 3) التشغيل على Linux / macOS
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m flask --app app seed
python app.py
```
ثم افتح http://127.0.0.1:5000

## 4) الوظائف
- إضافة كتاب بعنوان ومؤلف وISBN، وسنة نشر اختيارية وعدد نسخ.
- البحث بالعنوان أو المؤلف أو ISBN.
- إعارة نسخة باسم المستعير؛ ينقص عدد النسخ المتاحة.
- تسجيل الإرجاع؛ يزيد عدد النسخ المتاحة.
- حذف كتاب، مع منع الحذف إذا كانت له إعارات غير مُعادة.
- رسائل نجاح وخطأ بالعربية.
- تخزين البيانات في `library.db`.

## 5) الاختبارات الآلية
أوقف خادم Flask إن كان يعمل، ثم من مجلد المشروع ومع تفعيل البيئة الافتراضية نفّذ:

```bash
pytest -v
```

ستظهر كل حالة باسمها وحالتها `PASSED` أو `FAILED`، وفي النهاية ملخص مثل `11 passed`. الاختبارات تستخدم قاعدة بيانات مؤقتة ولا تغيّر بيانات المكتبة الفعلية.

لحفظ تقرير نصي:
```bash
pytest -v > test-report.txt
```

## 7) بيانات تجريبية
أمر `flask seed` يضيف ثلاث سجلات إذا كانت قاعدة البيانات فارغة:
- مقدمة في بايثون — أحمد علي — `DEMO-1001` — 3 نسخ
- أساسيات الشبكات — سارة محمد — `DEMO-1002` — نسختان
- قواعد البيانات ببساطة — محمد عثمان — `DEMO-1003` — نسخة واحدة

إذا أردت البدء من الصفر، أوقف التطبيق واحذف `library.db` ثم شغّل أمر seed من جديد.

## 8) ملاحظات
- هذا مشروع تعليمي محلي، وليس نظاماً إنتاجياً جاهزاً للنشر العام.
- غيّر `SECRET_KEY` وأضف تسجيل دخول وصلاحيات وحماية CSRF قبل أي نشر حقيقي.
- رسائل التحقق من الخادم هي الأساس؛ تحقق المتصفح تحسين إضافي فقط.


## 9) النشر على Render

تمت إضافة `Procfile` و`render.yaml` وتجهيز التطبيق للعمل مع Gunicorn ومتغيرات البيئة. ملف `render.yaml` يجهز قرصاً دائماً لقاعدة SQLite حتى لا تضيع بيانات المكتبة عند إعادة النشر؛ خدمة Render التي تستخدم قرصاً دائماً تحتاج خطة مدفوعة.

1. ارفع محتويات هذا المجلد إلى مستودع GitHub جديد.
2. افتح https://render.com وسجّل الدخول بحسابك ثم اختر **New + → Blueprint**.
3. اربط مستودع GitHub الذي رفعت إليه المشروع، ثم وافق على إنشاء الخدمة والقرص الدائم.
4. بعد اكتمال النشر سيظهر رابط الموقع في لوحة Render تحت **Live URL**.

لا تشارك مفاتيح الحساب أو كلمات المرور. لا يوجد رابط عام للموقع قبل إتمام النشر من حسابك.
